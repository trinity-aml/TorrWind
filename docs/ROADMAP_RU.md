# План завершения TorrWind

## Реализовано

- Реализован набор функций MVP из `PRODUCT_SPEC.md`.
- Настройки, журналы, резервные копии, плейлисты, данные TorrServer и пакеты обновлений находятся внутри каталога приложения `Data`.
- При наличии данных TorrWind проверяет SHA256 загрузок TorrServer и TorrWind из metadata GitHub или соответствующего checksum-файла.
- Файлы конфигурации локального TorrServer заменяются атомарно.
- `TorrWindService` работает от `LocalService`; установка выдаёт этой учётной записи доступ к `Data`, а интерактивному пользователю — только права запроса состояния, запуска и остановки службы.
- JSON-локализации загружаются только из файлов непосредственно в `locales`; повреждённые новые файлы не сбрасывают уже работающий перевод.
- Windows CI собирает и тестирует каждый push в ветку и pull request. Перед публикацией релиза выполняется отдельная обязательная сборка и тестирование.

## Оставшаяся приёмочная проверка

Эти проверки требуют настоящей Windows и ненадёжны под Wine:

- Smoke-тесты portable-версии и установщика на Windows 10 x64 и Windows 11 x64.
- Чистая установка и обновление существующей `TorrWindService`: проверить учётную запись `LocalService`, запуск и остановку без UAC, автозапуск и доступ к `Data`.
- Обновление и удаление через установщик, автозапуск, ассоциация `.torrent` и регистрация `magnet:`.
- Tray, WebView2 Web UI, тёмная/светлая/системная темы, DPI и масштабирование.
- Встроенный mpv для MKV, AVI, MP4, M3U/M3U8: перемотка, полный экран, выбор дорожек и плейлисты сериалов.
- Smoke-тесты локального и удалённого TorrServer, HTTP-аутентификации, игнорирования ошибок самоподписанного сертификата, Torznab-поиска, DLNA и WebDAV.

Найденные ошибки следует оформлять как воспроизводимые issues с версией TorrWind, версией Windows, шагами и support bundle.

## Условный Phase 2: подписи релизов

Официальные [релизы YouROK/TorrServer](https://github.com/YouROK/TorrServer/releases) сейчас публикуют SHA256 для файлов, но не предоставляют стабильный формат отделённой подписи и закрепляемый публичный ключ. SHA256 защищает целостность загрузки, но сама по себе не подтверждает издателя.

Проверка подписи будет реализована, когда upstream предоставит весь контракт доверия:

1. Документированный формат файла подписи или подписанного манифеста.
2. Официальный публичный ключ и стабильный fingerprint для закрепления в TorrWind.
3. Процедуру замены и отзыва ключа.

После этого TorrWind закрепит доверенный ключ, будет проверять подпись манифеста до принятия digest файла, отклонять отсутствующие или неверные подписи для подписанных релизов и получит тесты корректной подписи, изменённого файла, чужого и заменённого ключа.
